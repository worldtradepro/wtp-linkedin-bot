================================================================================
EPC RADAR — SOURCE LIST 维护指南
================================================================================

【设计原则】
本source list的目标是捕捉大型资本项目和采购信号，而非追求source完整性。
质量优先于数量——10个高产出source胜过100个零产出source。

【抓取策略优先级】
  rss        → 最稳定，优先使用。feedparser直接解析，有发布时间
  wp_json    → WordPress站点，API稳定，次选
  html       → 直接抓列表页，需定期验证URL有效性
  html_weak  → html抓不到时降级，会自动fallback到google_news
  google_news → 兜底策略，通过Google News RSS搜索公司名

【Source分类】
  5星 — 项目业主/运营商官网（信号权威，但发文少）
  4星 — 专业垂直媒体/设备商/多边机构（产出稳定，质量高）
  3星 — 综合媒体/贸易商/港口（产出多，噪音也多，靠Gemini过滤）

【日常维护原则】
  1. 不追求零产出=问题。大公司发文少是正常的，不需要处理。
  2. 真正需要处理的是404/403/DNS失败——这些source永远不会产出，
     只会浪费请求时间。
  3. 处理方式：404/403 → 改为google_news策略；DNS失败 → 删除。
  4. 每1-2个月跑一次probe_sources.py，更新失效URL。

【probe_sources.py使用】
  python probe_sources.py                    # 探测所有source
  输出：probe_report.txt
  关注：✗ INVALID URL 和 ✗ UNREACHABLE 两个分类
  处理：将404/403的source在第6列加上 google_news
       将DNS失败/长期unreachable的source删除

【增加新source的标准】
  优先增加：
  - 行业垂直媒体（比公司官网更稳定，产出更高）
  - 有RSS feed的source（最稳定）
  - 专注于项目/合同/采购新闻的媒体
  避免增加：
  - 纯价格/市场分析媒体（噪音多，Gemini也难过滤）
  - 已知强bot防护的大公司官网（用google_news代替）
  - 小型/低频更新的媒体（投入产出比低）

【格式说明】
  格式: 类别 / 子类别 / 名称 / URL / 信用星级 / [google_news可选]
  第6列 google_news = 不抓URL，改用Google News RSS搜索公司名
